## Citing specific tools

For reproducibility, include the **tool name**, **version number**, and **build date** for each containerised application that you used in Neurodesk. Also cite the original publications for each tool, as well as Neurodesk. You can get this information in two ways:

- [Copy the citation from the Applications catalogue](#copy-a-citation-from-the-applications-catalogue) for one tool.
- [Run `neurodesk-cite` in Neurodesktop](#generate-a-citation-list-with-neurodesk-cite) to get a citation list for all the tools that you loaded.

Where available, the **Container DOI** link in the application list identifies the packaged software version on Zenodo. Cite that record to identify your computational environment, and cite the tool papers to credit the underlying methods.

:::note[Citing EEG/MEG related tools]
If you used any EEG/MEG/electrophysiology tools, please also cite the AEDAPT project.
:::

### Copy a citation from the Applications catalogue

Each card in the [Applications catalogue](/overview/applications/) has a **Tool citations** row. If the tool's recipe has a citation, the row shows it, and DOIs and URLs in it are links. The row has these buttons:

- **Copy citation** copies the tool's citation text. It appears only when the tool has a citation.
- **Copy methods text** copies a methods sentence for the latest version of the tool, followed by a reference list with the tool's citation and the Neurodesk paper.

The methods sentence has this format:

<Code code={`ants (v2.6.5, built 2026-10-12) was run in Neurodesk (v${jupyterNeurodeskVersion}, Renton et al., 2024).`} lang="text" />

The copied sentence names the latest version in the catalogue. If you used a different version, change the version and build date to match. To see all versions and their build dates, expand **All Versions** on the card.

If a tool has no citation in the catalogue, find the tool's directory in [neurocontainers/recipes](https://github.com/neurodesk/neurocontainers/tree/main/recipes) and look for references in `README.md` or the `readme` section of `build.yaml`. Follow the tool authors' guidance for the methods you used. For example, the [FSL recipe](https://github.com/neurodesk/neurocontainers/blob/main/recipes/fsl/build.yaml) includes overview references and directs readers to the individual tools' manuals.

### Generate a citation list with neurodesk-cite

Neurodesktop records each Neurodesk tool that you load. The `neurodesk-cite` command turns that record into a `CITATIONS.md` file with a methods sentence for each tool version and one reference list.

:::note
`neurodesk-cite` is available in Neurodesktop releases after 2026-09-23. Older images do not record tool loads.
:::

#### What Neurodesktop records

Neurodesktop adds one line to a usage log each time a Neurodesk module loads. The line has the module name, the version, and the time in UTC. Loads from these places are recorded:

- `ml` and `module load` in a terminal.
- Notebook kernels and the module side panel in JupyterLab.
- Applications in the desktop menu.

The log is `~/.local/state/neurodesk/module-usage.tsv`, or `$XDG_STATE_HOME/neurodesk/module-usage.tsv` if you set `XDG_STATE_HOME`. Only Neurodesk modules from CVMFS or from local containers are recorded. The log stays only in your home directory, and Neurodesktop does not send it anywhere. Your home directory is persistent in the standard Docker and hosted setups, so the log is kept when you restart Neurodesktop.

#### Write CITATIONS.md

To write the citation list, run this command in a Neurodesktop terminal:

```bash
neurodesk-cite
```

The command writes `CITATIONS.md` to the first of these locations that is a writable folder:

1. `~/neurodesktop-storage`
2. `/neurodesktop-storage`
3. Your home directory

The file has one entry for each tool version, in the order that you first loaded them. If you loaded a tool many times, it is listed once. Remove the tools that your analysis did not use before you add the text to a paper.

These options change what the command does:

| Option | Effect |
| --- | --- |
| `--since YYYY-MM-DD` | Include only loads on or after this date. The date is in UTC. |
| `--output PATH` | Write the file to `PATH` instead of the default location. |
| `--clear` | Empty the usage log and exit. You cannot restore the cleared loads. To leave out older loads without deleting them, use `--since`. |

For example, to write the citations for one project into the project folder:

```bash
neurodesk-cite --since 2026-11-01 --output ~/neurodesktop-storage/my-project/CITATIONS.md
```

#### Use neurodesk-cite offline

`neurodesk-cite` downloads the catalogue each time it runs and keeps a copy in `~/.cache/neurodesk/`. If the download fails, the command uses the copy and prints the date of the copy. If there is no copy, the command still writes `CITATIONS.md`, but without build dates or tool citations, and it prints a warning.

## For tool maintainers

The citation for each tool comes from its recipe in neurocontainers, `recipes/<tool>/build.yaml`. Neurodesk uses `structured_readme.citation` if the recipe sets it. Otherwise, it uses the `Citation:` section of the readme. The Applications catalogue and `neurodesk-cite` read the citation from the catalogue data, so a change to the citation does not need a container rebuild. To add or fix a citation, open a pull request in [neurocontainers](https://github.com/neurodesk/neurocontainers) that changes `build.yaml`.
